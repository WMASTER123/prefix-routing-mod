# 决策：预装组合首验，公共 Qwen2.5-14B，最小功能先行

日期：2026-10-11。用户已确认基线选择；本决策不等同生产能力放行。

最新运行环境选择由[HUST 隔离候选决策](2026-10-11-hust-runtime-candidate.md)替代；本文保留早期选择及其成绩范围，不再用于把指定 HUST 后置。模型和阶段边界继续适用。

## 决定与依据

- 优先使用验证通过的预装 vLLM 0.23.0 / Ascend 0.23.0，固定实际源码提交；两份 HUST 归档组合后置兼容验证。不覆盖全局环境。
- 使用公共 Qwen2.5-14B-Instruct；当前 4×910B2，每卡 64 GiB。先单卡 TP=1 基础生成，再双副本接线，最后四副本容量。四卡是四个潜在路由目的地，不默认 TP=4。
- 基础闭环不依赖完整 ExecutionProfile、图状态输入或 N0–N6 全覆盖。按实际瓶颈引入增强；不把 NPU 学习资料逐条转成产品功能。
- 预装 Ascend 的 ARM 默认 CPU binding 路径可能操作 IRQ/irqbalance；探测显式禁用，Host 优化后续仅在获准进程/cgroup 范围内验证。
- 原生 APC、事件和指标先验收；不能因探测接线错误、字段名含 GPU 或单次未收到事件而直接判定必须增加 observer。

## 当前不决定

不冻结生产 Router 底座/语言，不实现新网关或缓存树，不调整淘汰、图执行或算子；不选择评分算法。P1a 仍需验证成熟候选的真实接入点、aarch64 成本、生命周期和索引恢复，再决定复用范围。

## 失败和回退

任一能力按配置单独记录。生成成功不证明精确缓存状态或恢复正确。原生事件未达到要求则暂缓精确模式，先诊断；若需引擎 hook、额外依赖或更换组合，提交证据并讨论。Manager 继续 import_only，未实现功能不能启用。
