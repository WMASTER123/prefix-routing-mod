# 控制新鲜度、保债与恢复

状态：实现候选；CPU、固定宿主与双 NPU 结果分别记录后放行。

在原有 `recovery-retirement-v1` 上增加进程内控制门，不改变持久 schema、来源绑定、终态结算和 commit→ACK→retire 顺序。控制门由 M7 更新，M3 在候选快照、reserve、before_send 三处读取；HTTP 请求不执行控制 RPC。

- 每个后端绑定固定 instance/observer/ownership。新门默认关闭；控制请求发出前取得 ticket，经固定适配器完整核验后，才以请求发出时间加 TTL 开放。
- 控制错误立即撤销新准入；即使后台线程卡住，读取时也会检查单调期限。更新不能延长已经过期的旧请求，旧 ticket 不能覆盖新一轮检查。
- 同身份重新验证可以恢复；身份冲突永久隔离这个门，必须另行走实例交接，不能重贴旧债。普通 KV 帧或普通 HTTP health 不续期。
- 每次关闭递增发送围栏。即使同实例已恢复，关闭前取得的未发送 lease 也不能重新发送。已发和 uncertain 记录保持原账本；可靠终态仍可结算，重复终态不重复释放。
- 排空是不可逆的本进程状态：关闭新准入，继续处理已发送终态。超时不能把未决记录清零；下次进程按既有暂停恢复合同接管。
- 控制门和本地期限不持久化。重启必须构造全新的关闭门，实际验证后才使用。尚未安装控制门的旧 CPU oracle 保留原语义，真实公开链必须显式安装。

首个候选仍使用回环服务和单 Router；不增加跨主机租约。TTL 与刷新周期是显式资格参数，尚未校准为生产默认。当前 Manager manifest 仍 `import_only`，不能因增加排空原语提前宣布可激活。
