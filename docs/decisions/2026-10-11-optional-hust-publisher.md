# 可选 HUST publisher hook：实验准入决策

状态：用户已同意实现并实验验证；不是生产启用或最终复用底座冻结。

## 实证原因

固定 core 13f11da 的 producer 先更新镜像、发布线程后分配序号，已复现共同水位反例。原生快照只有哈希，没有 token/parent；实时帧没有 epoch。固定 Router 91b65ee 的索引按本地 token 块键匹配，引擎哈希为关联键，不能直接用仅哈希快照重建。

tools/prototype_kv_boundary.py 已用固定 HUST 的真实镜像/重放方法验证单 owner 提交顺序。原型没有安装到引擎。用户选择优先实现可选小型 hook，实验确认维护成本和开销后再决定交付。

## 本轮实验实现边界

- 独立 general plugin，默认关闭；安装本 MOD 不自动替换 publisher。显式开关和 allowlist 同时配置后才走实验入口。
- 用固定版本与 publisher 文件 SHA-256 守卫；只在当前项目隔离环境测试。原生引擎源码不编辑。实验 hook 通过受守卫的工厂绑定覆盖 zmq 构造器，属于内部接入点，须单独维护与验收。
- producer 仅入队；publisher 线程先编码，再更新镜像/重放缓冲/排他序号，PUB 失败仍可重放。序列化/元数据失败撤销恢复资格。
- 保存有上限的块 token/父链元数据。快照先恢复拓扑，再撤销已淘汰祖先的驻留；消费者必须在暂存状态中完整应用后原子替换，不能逐条开放快照命中。
- 实验实时协议四帧：topic、8 字节序号、原生 batch、ASCII epoch；结构化重放回复增加 schema_version=1、valid、reason。消费者必须校验协议、epoch、完整区间与 payload 上限。
- 只准入 TP=1、DP rank 0、纯文本、group 0、完整块；LoRA/extra keys/部分块遇到时停止精确恢复资格，明确反馈，后续再按功能验证扩展。
- 默认元数据上限 16384 块/2097152 tokens，单个 payload、重放缓冲总 payload 和回复各有 16 MiB 上限；缓冲还受原生批次数上限约束。达到元数据上限先回收无驻留依赖的数据，仍超限则降级。reset 后真实清空事件可以建立新代次，不以 HTTP 返回代替。这些是逻辑限额，不等同进程 RSS 或峰值内存已测量。
- 原生无 hook 组合保留；MOD 仍 import_only。四帧协议和恢复适配不是现有 Router 订阅器可直接消费的接口，需后续 Router 侧接线。

## 本轮验收

CPU 覆盖默认关闭、守卫、重复加载、共同水位、编码/发送失败、元数据限额、已淘汰祖先、清空和代次。真机先验证已热服务冷接入、超过重放窗口后完整快照、快照后增量及真实清空；同地址重启及压力/开销另有独立通过条件。纯文本身份先独立复测，不能用 hook 绕过 tokenizer 不一致。

M1–M8 职责不变，不增加在线服务，不重写生产索引。vLLM Router 的代理/策略仍是候选；本轮只形成可审查的 publisher 适配及其证据。未经 aarch64 构建、接线和资源成本验收，不将候选库写为已采用。
