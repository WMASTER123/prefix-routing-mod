# ADR：Ascend 优先的规划与性能证据边界

日期：2026-10-11。状态：规划约束已采用，运行实现与性能待验收。保留编号 002–005 供原有待决项使用。

问题：旧规划虽然以 Ascend 为部署目标，仍不足以约束复用中的 GPU 依赖、命中到实际节时的映射、图/Host 成本与 NPU 组合验收。

证据：用户 NPU 知识库、一手 Ascend 图/功能/CPU 绑定文档，以及本项目已有只读硬件清单。阅读范围和链接见 [Ascend 设计说明](../ascend-design.md)。这些不是 NPU 运行结果。

选项：全部重做 NPU 专用组件，成本高且没有证据；原样搬用 GPU 系统，语义和性能风险未被控制；保留通用组件并为设备相关假设设置验收门槛。

决定：选择第三项。保留一个外部 Router 与 M1–M8，不增加 P/D、分层、KV 搬运、算子或引擎调度改造。引入能力描述与执行校准档案合同，分开语义/缓存布局与协议/执行性能身份。复用通过构建、语义、性能三道门槛；先做 N0–N6 服务验证，再按消融收益选择方法。

代价：P1/P2 多出显式 Ascend 整栈与曲线验证，需要独占时段；在线图/阶段状态可能无法获取，不能保证高等级增强可用。收益：避免用错误成本模型优化，避免观测扰动、误判容量或迁移不适用的实验结论。

退出/调整条件：某个硬件相关输入不可低成本获得或无稳定收益时，关闭对应增强并维持经验证的基础策略；更换执行配置重新确认档案适用性。运行/API 字段仍在 P0/P1 定稿，本 ADR 不把规划写成已支持功能，也不授权改宿主环境。

文档版本：docs/reference 保留建仓快照；docs/planning 保存当前三份完整规划，活文档提供执行入口。桌面工作区副本与仓库正文同步，仅相对链接按位置转换。后续变更同步维护，不能继续把快照当最新实施指令。
