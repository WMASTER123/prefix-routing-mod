# 在线传输观察接线：CPU 实验边界

日期：2026-10-13。延续已批准的 CPU 接口评估，不安装引擎 observer，不改变 component-v0.1 或 MOD import_only。

原生 Lease 回调要求本地、有界，不能在回调中做网络等待或 SQLite FULL 提交。继续复用已有每尝试至多两条的 LifecycleTrace，在准入前注册有限槽位；显式控制线程读取未确认记录，向 loopback 实验接收端投递，提交后确认，失败保留原记录。回调不新增网络、磁盘、设备同步或逐 token 事件。网络故障锁住新派发，恢复投递本身不解除该锁。

传输观察序号与账本生命周期序号分离：账本单写者校验观察身份和每尝试顺序，分配生命周期序号，并把来源及结果在同一事务记录。重发使用原始载荷；已经可靠结清后的迟到传输关闭只确认观察，不重开负债。HTTP 状态、EOF、drop 都不产生后端 ENDED。

实验通道仅接受 127.0.0.1，使用每次运行随机 capability、长度前缀、消息上限与 socket deadline。不提供远程 TLS、多租户认证或公开服务。Python 接收进程只是故障实验接收器；生产仍为单 Router owner，不据此增加生产账本服务或选定 Python/SQLite 热路径。

完整宿主实验预先持久化有限合成请求预留，之后启动原生 Router：避免观察到发送后再伪造预留。未使用的预留仍保留，单独报告；这不证明动态 HTTP 准入、真实身份/分词或完整终态关联。实际转发仍由固定 Router 与已有三个文件 patch 完成。

本轮退出条件：实际回调在 Router 存活时更新同一账本；确认丢失/断连可重投；接收侧重建可去重但不恢复新派发；超限拒绝不丢未决记录；禁用时原回归通过。留存槽位暂不回收，源进程丢失尚未投递记录时预留保持未知；长期 GC、启动对账和业务结果与逻辑结束组合仍需后续实现。
