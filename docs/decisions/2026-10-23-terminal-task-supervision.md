# 终态后台任务的监督、就绪与停止边界

日期：2026-10-23。续接[单来源驱动](2026-10-22-terminal-driver.md)。本轮实现与资格状态见 [progress](../progress.md)，不以设计文字代替实际运行结果。

原有限入口在请求之间调用 step。新装配把同一 TerminalDriver 移交给每来源唯一 TerminalTask，运行原持续循环；HTTP 侧只能读取有界进度，不能再运行原 reconcile。驱动、账本、HUST HTTP 运输和来源绑定均保持唯一。调用方必须核对来源集合不重复且覆盖持久 cursor；TerminalTask 本身不是全局注册表或进程 Manager。

每来源只有一个 watch 快照：阶段、已提交水位、待远端确认标志、最近成功时间。它不保存请求记录，不是恢复权威；恢复必须读原持久账本。首次完整 step 成功后才可能就绪；失败重试、未启动、已停止、任务退出和成功时间过期均不就绪。Working 期间可沿用未过期成功时间，避免每次轮询制造 readiness 抖动，但不能算排空完成。最终服务仍须结合控制门、持久恢复、HTTP 工作及监听状态计算整体 readiness。

停止顺序要求：关闭准入和服务 readiness → 等自身 HTTP 工作结束及真实负债结清 → 等全部来源确认完成 → 同时向各任务发 stop → 逐个 join → 核验最终 pending 标志 → 关闭订阅和存储。不能先 join 一个来源再停其他来源，因为每个任务的退出保护都会关闭共享 owner。进度快照只能作为等待提示，不能替代 join 后检查。停止请求不承诺已经回收成功；远端持续不可用时允许返回待确认，保留持久 cursor，供重启重新确认。

正常停止在有界操作之间生效。丢失监督句柄或取消 join 会关闭准入并设置停止请求；后台操作完成后退出，不直接 abort 正在进行的持久提交、ACK 或 retire。任务 panic/异常退出要通过 join 暴露，不能变成成功排空。此保护不能替代进程强退的持久恢复合同。

HUST 运输增加七种已校验核心状态的饱和累计诊断，只有对应批次持久提交成功才累计一次。ACK/retire 重试和 idle poll 不重复累计，也不从这些诊断产生结算证据。计数不落入恢复合同，不保存请求原文或身份历史。

真实入口的显式 `--background-terminal-driver` 仅用于有限资格，与 `--use-terminal-driver`、managed durable 模式一起使用；拒绝混合尚未验证的恢复、churn 和控制故障模式。它等待实际来源水位验证路由，覆盖关闭准入后流式取消、后台结清、确认和 join。该模式没有完整 SIGTERM/HTTP 工作计数、公开 readiness 端点、生产启动恢复或 Manager 激活，不能将其标成完整常驻产品。MOD 仍为 import_only。

用户本轮明确暂不讨论人员分工；继续按唯一所有权和合同推进实现、回归与自审，不把指定人员作为推进条件。
