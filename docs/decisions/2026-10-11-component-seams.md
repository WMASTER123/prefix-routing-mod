# ADR：先交付可执行组件边界，不提前冻结 Router 宿主

状态：研发候选，待另一成员审查。日期：2026-10-11。

用户要求先有能独立分工的架构、接口和联调基础。新分配为 CPU-only aarch64；真实推理仍遵守 G1→G2→G3→G4。CPU 合同与宿主构建准入不必等待全部真机门槛，但不得据此启用生产 Router。

## 决定

- 首个闭环为一个外部 Router + 已有同模型副本 + 可选固定版本 publisher。M1/M2/M3/M4 在宿主内调用，M5 复用宿主转发；不拆八个服务，不新增逐请求 RPC。M6 离线，M8 后置且可关闭。
- 发布 `component-v0.1` 的 Python 标准库参考类型、端口与测试。它们定义语义和状态所有权，不意味着生产热路径选了 Python；宿主若选 Rust，必须通过同一组行为用例后做等价映射，不在请求路径来回 JSON/Python/Rust 转换。
- `WorkerRef.instance_epoch` 是服务实例身份，`CacheRef.publisher_epoch` 是发布流身份。发布器重连/换代只撤销对应 M2 信任；不能清除仍运行实例的 M3 在途账本。
- M3 是预记账唯一写入者。M4 只选点，M5 发送前调用 M3 原子条件预记账；失败重新读取/选择。发送后不确定保留对账负债，不作为安全重试依据。
- 测试内提供有界账本和静态目录 fixture，验证跨组件协议；不实现第二套生产代理/驻留索引。最终生产组件必须自行满足线程安全、资源和故障合同。
- `PlacementPlan`、性能成本档案、部署管理不纳入本次可执行合同；已有设计合同保留，在真实消费者出现时版本化，避免空接口冻结。

## 宿主准入未决项

固定 Router `91b65ee4bdfbe98863a32a2205dced5dbb249ffe` 的普通策略入口接收 text/headers，普通 model policy registry 没有公开自定义实例注入入口；现有 KV 索引未接在线策略。发送/流式终态、取消与重试还需审计。不能只替换 policy 就假定 M1–M5 完成。

先做原提交 Linux aarch64 构建探针和扩展面清单，保留失败根因；不改其 Cargo 依赖绕过失败。若需要大面积 Router fork、换底座或自建代理，先向用户讨论，不能用本 ADR 推定授权。生产绑定代码、二进制布局和 MOD enablement 因此仍未冻结。

## 兼容与回退

静态 config schema=1、现有 MOD manifest 和 opt-in publisher 不变。新接口是可审查的研发契约，不对外承诺稳定 API；改字段须升契约版本并更新 fixtures。包及合同导入无引擎、线程、网络或设备副作用。真实环境和已通过实验不覆盖。
