# 前缀路由 MOD：项目接手、组件分工与接口边界

更新日期：2026-10-17。适用对象：三人研发团队及后续接手人员。本文是接手入口，当前完成状态以 [progress](progress.md) 和对应 `evidence/` 为准；历史文档按当时日期解释，不能把旧版 hook、旧环境或局部测试当作当前交付能力。

## 1. 项目要做什么

面向华为 Ascend NPU 上同模型、同构、多副本 LLM 服务，提供易接入、可诊断的前缀路由 MOD。结合真实可复用前缀和副本在途状态分配请求，在相同 NPU、CPU、内存资源下提高满足 TTFT、生成停顿和完成率要求的有效服务容量。是否优于现有系统由强基线实验判断，目前没有性能领先结论。

接入已有模型服务并提供启动示例和检查工具；一个外部 Router 承载在线路径，Python 包承担 MOD 描述、诊断和窄幅版本适配。M1–M8 是职责划分，不是八个网络服务。当前优先完成固定 HUST 组合；版本映射用于集中差异，不能保证任意 vLLM 版本只改字符串即可使用。

首版不包括 P/D 分离、分层缓存、KV 搬运、异构调度、引擎淘汰替换、多 Router 高可用和模型部署平台。M8 后台优化可后置，不作为分工或基础版本验收的必要前提。

## 2. 已选定的框架与复用关系

```text
客户端
  └─ M5：原 Router HTTP 入口
       └─ M1：本地分词与完整块特征
            └─ M4：读取 M2 驻留观测和 M3 状态，输出选点决定
                 └─ M3：复核版本/实例/额度，预留并持久提交
                      └─ M5：取得许可，原 HTTP/SSE 转发
                           └─ HUST 推理副本（各 TP=1）
                                └─ M7：真实完整终态 → 同一个 M3

HUST KV 事件/实例控制 → M7 → M2 原索引/Directory/Pool
M6：链外测试、校准、压测与报告
M8：后续可关闭、有时效的软亲和计划
```

| 组件 | 职责与输出 | 复用与自研边界 | 当前主要代码入口 |
|---|---|---|---|
| M1 请求特征 | 有界解析、本地 tokenizer、身份与完整前缀块摘要 | 复用本地 Qwen tokenizer；自研身份/范围校验和特征桥，不逐请求远程分词 | `experiments/router-extension/request_feature_port.rs` |
| M2 KV 目录 | 真实驻留的连续前缀查询、unknown/失信/资源预算 | 复用固定 Router 原 KV 索引，扩展 Directory/Pool；不新建第二棵生产树 | `experiments/router-index/src/{directory,pool}.rs`、`runtime_cache_port.rs` |
| M3 状态与账本 | 唯一准入、预留、在途负债、终态结清和恢复所有者 | 复用基础状态能力，自研条件准入与可靠账本；SQLite 是候选介质 | `runtime_owner.rs`、`durable_runtime.rs`、`runtime_store.rs`、`sqlite*_runtime_store.rs` |
| M4 选点 | 从合法候选中选择目标，输出实例/配置围栏 | 当前基础策略：可信正命中优先，否则最低在途/稳定 URL；高级策略尚未实现 | `runtime_provider.rs` 的 `RuntimeProvider` |
| M5 接入与执行 | HTTP/SSE、发送前复核、实际发送与传输关闭事件 | 复用固定 Router 的 HTTP/连接/转发；只保留已审接缝，不增加 Python 推理代理 | `prefix_extension.rs`、宿主 patch、`hust_runtime_probe.rs` 装配例 |
| M6 评测与交付 | 可复现负载、故障、开销、容量曲线、制品检查 | 复用现有测试/构建工具，统一公平比较和统计口径 | `tools/`、`tests/`、`.github/workflows/`、`benchmarks/` |
| M7 适配与观测 | 源码/版本守卫、实例身份、真实 KV 订阅与终态观测 | 使用 HUST 实际接口；必要的只读包装默认关闭，不改调度/分配/淘汰/设备执行 | `src/prefix_routing_mod/adapters/`、`hust_terminal.py`、`terminal_transport.py`、`native_kv_*.rs`、`hust_source_control.rs` |
| M8 后台优化 | 根据有界历史发布可过期的软亲和建议 | 仅有职责/契约规划，待基础性能证据后决定机制 | 生产实现尚无，不应另起控制服务 |

表中未写目录前缀的 Rust 文件均位于 `experiments/router-extension/`。它们已有可运行代码，但仍是候选位置；正式迁入生产目录时统一调整调用方，不能每人再实现一套。

## 5. 接口怎么对接，哪些边界不能混淆

下表是当前真实候选接口，不是已经冻结的生产 ABI。Python `component-v0.1` 是参考模型与 fixture，不能把其字段直接当成 Rust 宿主二进制接口。

| 调用方向 | 实际接口/数据 | 必须遵守的语义 |
|---|---|---|
| M5 → M1 | `FeaturePort.extract(request, route) -> RequestView` | 当前字符串 completion；输出 `request_id/identity/block_hashes/exact`。未验 chat/template、数组、token-id、LoRA/多模态不得静默接入 |
| M4 → 状态视图 | `SnapshotPort.candidates(features, available) -> Vec<Candidate>` | 含 worker/instance、worker/config 版本、健康/排空、local_outstanding、matched_blocks；M2 与 M3 不构成跨组件全局事务快照 |
| M3 → M2 | `CachePort.lookup(worker_url, instance_epoch, identity, hashes) -> Option<u32>` | 数值是完整匹配块数，不是 token 或节省耗时；`None` 是 unknown，`Some(0)` 才是可信未命中 |
| M4 → M3 | `allocate_attempt`、`reserve_async(features, decision)` | attempt 不复用；选点不产生发送资格。reserve 复核实例/版本/额度，持久提交确认后才返许可 |
| M3 → M5 | `Lease.before_send/sent/headers/closed` | before_send 再复核围栏；回调本地有界、不得阻塞磁盘/网络或设备同步。传输关闭不结清已发送负债 |
| M7 → M2 | `NativeTransport`、`SourceControl`、`NativeKvOwner`、`InProcessCache` | 每分区一个订阅 owner；缺口/断连/身份不符撤销信任，普通实时帧不能自动恢复失信目录 |
| M7 → M3 | 完整 `TerminalRecord` 批次和 `TerminalCursor` | cursor 绑定 source/worker/instance/observer；整批核验后结算，同一事务持久账本与 cursor，随后才能 ACK |
| M3 → 存储 | `RuntimeStore.initialize/load/commit/takeover` | create-once、owner/generation CAS；错误或提交不确定时暂停准入；重启不能初始化空账本抹除负债 |

实例 `instance_epoch`、终态 `observer_epoch`、KV publisher/连接代次是不同概念。当前 HUST 原生 KV 没有可外推的完整 publisher epoch/共同水位 token 快照；本地连接号不能冒充后端发布代次。

KV 目录是异步驻留观测，不是 pin 住缓存的承诺。M2 失信可以回基础负载策略；M3 不可信/存储失败不能绕过准入。M4 只能读状态和选点，不能直接改目录、账本或引擎缓存。

调用与并发：HTTP 在 Axum/Tokio 上处理；当前 M1 在本地同步提取，CPU 竞争须实测。每个后端的原生 KV owner 使用独立阻塞任务/线程；M2 查询只做本地有界读。M3 在短状态锁下修改内存，持久包装用异步提交门和有界等待槽，磁盘操作放入 blocking 任务；Lease 同步回调不得承担落盘。锁顺序、排队/取消/过载行为的改动须连同调用方一起审查。M2 的 `ClockPort` 使用本进程单调纳秒，不跨进程比较数值。

配置与错误仍有待冻结的具体问题：`configs/example.json` 只是 schema_version=1 的静态 model/domain/workers 配置；实机装配的私有 JSON 不是同一个公开 schema，不能各组随意往示例里加字段。Rust 候选仍主要返回静态错误字符串，宿主接缝把多数扩展错误映射为 503，只有请求编码等少量路径为 400；生产必须统一无效输入、容量拒绝、实例变化、存储不确定等错误与可重试性。当前行为不得被误当成已经认可的最终 HTTP 合同。实验中的 500ms 刷新、64 等待槽、5s 提交期限等也不是已校准生产默认值。

恢复时保留旧 active 并转为 uncertain，默认禁止新发送。`previous_dispatcher_stopped` 当前仍由调用方证明，生产的旧派发者围栏、健康新鲜度和恢复开放准入尚未完整验收。缺失记录、超时、HTTP 结束都不是后端已经空闲的证明。

终态 ACK、Frontend family 退役、Core 窗口回收是不同步骤。静态控制 token、`prm-` 前缀和不可猜 request ID 不能单独认定请求归属。首版选择专属副本池：后端仅回环监听，所有业务请求经 Router，Router 覆盖客户端 request ID；仅显式 `exclusive_router_v1` 才允许 retire，默认 `observe_only`。退役顺序必须是 M3 持久终态/cursor → ACK → 同水位 retire，禁止按 TTL 删除未知请求。

首版不允许其他业务客户端直连同一批受管 HUST 后端。这不是要求企业全部模型流量都走本 MOD，只约束加入该 Router 池的副本；其他服务可保持原样。若以后必须共享后端，需增加逐请求 proof/MAC、重放状态和不可见负载校正后单独验收，不能只切换配置。健康、指标和受鉴权控制调用不属于业务旁路。

## 6. 三人基本分工与可以立即开始的任务

以下 A/B/C 是工作包，尚未绑定具体姓名。各包均负责自己的测试和证据，交叉审查；集成负责人可轮值，但一次只有一人负责共享接线和服务器同步。

| 包 | 主要所有权 | 现在可以独立开展 | 接入前依赖与交付物 |
|---|---|---|---|
| A：M7/M2 | 固定版本 profile、KV 解码/订阅、身份/新鲜度、目录与资源边界 | 完善版本化 fixture、父链/缺口/实例替换反例、目录大工作集/内存测试、适配能力矩阵 | 通过已有 `CachePort`/source-control 交付；不得改变 M3 负债或直接清理终态 family。新观测字段先交接口评审 |
| B：M1/M4/M5 | 特征、纯选点、HTTP/SSE 与发送门 | 字符串 completion 输入边界、一次分词成本、基础策略纯函数测试、慢客户端/取消/默认关闭回归 | 复用 `RequestView/Candidate/Decision/Lease`，新支持的 chat/template 先定义完整身份；不另建代理、账本或目录 |
| C：M3/M6/交付 | 准入/持久提交/游标、恢复、公共评测和 MOD 生命周期 | 当前优先完成增量存储、真实 commit→ACK、故障/恢复；并行准备负载、分组/SLO 报告和制品诊断 | 账本唯一所有者；ACK/退役协议与 A 共同评审，接入生命周期与 B 共同评审；不能由 C 单独承担所有人的测试 |

**可以现在开始受现有端口约束的独立任务。** 生产目录迁移、恢复协议和 Manager 激活等跨包工作，先由集成负责人完成最小闭环，再冻结一个明确版本。无需等最终算法或完整容量实验结束才分工；也不能把仍在实验的存储/回收接口写成永久接口。

文件协调规则：

1. `runtime_provider.rs` 的共享类型、`prefix_extension.rs` 的宿主接缝、`runtime_store.rs` 的持久合同、Python manifest/config schema，由集成负责人统一落改动；A/B/C 提供变更和调用方反例。
2. A 主要修改适配/目录文件，B 修改特征/策略/转发，C 修改账本/存储/评测。`hust_terminal.py`、`terminal_transport.py` 属 A 的适配代码，但 C 使用的 ACK/退役语义必须共同审查。
3. 每人独立分支和工作区。公共 CI/构建锁由 C 协调，所有修改仍需对应组件负责人复核；不同时编辑服务器同一个 checkout。
4. 接口 PR 同时提交字段/单位/错误/线程/时钟说明、调用方、fixture、反例与回退。暂未冻结的字段只在候选范围使用，不各组复制出不同版本。

## 8. 开发、测试、服务器与审查规范

先读 [AGENTS](../AGENTS.md)、[CONTRIBUTING](../CONTRIBUTING.md)、[architecture](architecture.md)、[contracts](contracts.md) 和涉及的 ADR；性能/后端修改另读 [Ascend 设计](ascend-design.md)。`docs/reference/` 是历史引导快照，不能作为最新任务指令。

- 分支用 `codex/` 或团队约定的独立功能分支；小 PR，另一成员交叉审查，不自动合并。保持第三方来源与许可证说明。
- 复用前检查实际 HUST 源码/协议和固定制品。需要新增依赖时最小化 feature，比较 Cargo/Python 锁差异，禁止顺带升级原有包；差异不合理先停下诊断。
- 当前在线候选使用 Rust；Python 参考账本用于 oracle/诊断，不能再并行部署成第二个生产状态源。M6 压测/故障注入不进入请求链。
- 不在请求回调里逐次 `npu-smi`、profiler 或设备同步；不搬用 NVIDIA 成本系数、KV 布局假设或未经 NPU 实测的图配置。
- 包导入不初始化设备、加载 torch、创建线程或网络连接。未完成实现不得把 manifest 改为可启用。
- 不提交令牌、私有配置/原始提示、模型、原始私有日志和大制品；`artifacts/` 保留本机证据，Git 只放脱敏摘要、命令、hash 和适用范围。
- 每组先跑 CPU/对应 Rust 测试，再申请实机。NPU 测试先手动触发统一工具，后续才接硬件 CI；缺少硬件不报告通过。
- 无 NPU 的协议/存储工作用 CPU；单副本联调用 1 张，双副本隔离/路由/公平对照用 2 张。使用真实、有期限的实验，不运行绕过平台闲置策略的空载负载。
- 服务器只在本项目 `/root/work/prefix-routing-mod` 操作；`/root/work/prefix-router` 是无关旧项目。禁止使用本项目未授权的 SSH alias，禁止全局 pip、驱动/CANN 或公共模型修改。
- 启停工具只清理本任务创建的进程组；结束核对退出码和设备残留。重分配设备/端口/Host 配额后重新记录指纹，不能沿用旧性能档案。

CPU 开发入口：

```bash
uv sync --frozen --extra test
uv run --frozen python tools/check.py --suite cpu
uv run --frozen python tools/check.py --suite integration
uv build --offline  # 缓存齐备时；缺缓存则按锁补齐，不跳过依赖校验
uv run --frozen python tools/verify_wheel.py
cargo +1.99.0 fmt --manifest-path experiments/router-extension/checks/Cargo.toml --check
cargo +1.99.0 clippy --locked --manifest-path experiments/router-extension/checks/Cargo.toml --all-targets -- -D warnings
cargo +1.99.0 test --locked --manifest-path experiments/router-extension/checks/Cargo.toml
```

CI 三类入口为 `.github/workflows/ci.yml`、`router-extension.yml`、`router-index.yml`。固定 HUST 方法源码测试、CPU integration、wheel 干净安装、真实 IPC 和目标 ARM 实机各有范围，不能互相替代。example 是验收装配，不是最终用户启动器。

## 9. 首次接手检查与交接验收

1. 取得私有仓库权限，核对当前 PR 的 base/head 和本地 dirty 状态；当前完整研发成果不在 main。不要覆盖同伴未提交修改。
2. 读 progress、本文、架构、对应组件合同与最新 evidence，确认测试对应的提交/配置，而非仅看通过数量。
3. 跑自己工作包的现有最小测试，复用现有 fixture；给变更补必要反例，不复制另一组的数据类型。
4. 在任务卡写明代码所有者、输入/输出/单位、跨组件依赖、验收命令、是否需 NPU、回退方式；共享接口先统一再实现调用方。
5. 提交 PR 时说明问题、行为变化、已跑/未跑测试、成本与剩余限制；涉及接口时附调用方验证和交叉审查。

生产接口冻结须另有记录：固定提交、最终目录、类型/schema 版本、线程/锁/时钟、错误/降级、配置与启停语义、替身、兼容范围和通过证据。本文提供接手依据，不代替这些尚未完成的验收。
