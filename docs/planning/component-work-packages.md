## 首个交付到底是什么

一个接入已有模型服务的外部 Router MOD。首个基础闭环只包含健康/身份筛选、可信缓存查询、基础选点、预记账、转发与终态对账；随后同底座比较强缓存感知基线。第一版不要求 M8、成本预测或完整图遥测，否则无法区分联通失败与优化失败。

```text
                    同一个 Router 进程（语言/二进制待宿主准入）
HTTP -> M5 -> M1 -> M4 -> M3 条件预记账 -> M5 复用宿主发送/SSE
                  ^      ^                       |
                  M2     M3 状态快照 <------------+ 生命周期
                  ^      ^
                  M7 原生事件/健康与实例身份适配

已有 Qwen14B 副本独立运行；可选 publisher 在副本进程内。
M6 在请求链外测试/评测；M8 后续只提交可绕过的软计划。
```

MOD 包负责静态发现、检查与后续合法生命周期，不负责自动管理用户模型进程。现在继续 import_only，不因为有接口文件就放开 Manager enable。

## 组件端口与独占所有权

| 所有者 | 输入 → 输出 / 动作 | 不允许承担的职责 |
|---|---|---|
| M1 | 已解析且有界请求 → `RequestFeatures`；真实身份/模板/token，失败明确精度 | 不推断驻留，不逐请求向模型服务分词，不重复保存原始 prompt |
| M2 | M7 规范化事件与恢复 → 缓存视图；`CachePort.lookup` → `PrefixMatch` 元组 | 请求派发不得变成 BlockStored；未知不能当 miss；不修改引擎淘汰 |
| M3 | 健康/实例身份 + M5 事件 → `WorkerState`；`reserve` 原子条件预记账，`apply` 幂等对账 | 不合并 publisher epoch；不把本地 outstanding 当引擎真实 running |
| M4 | 特征、目录和状态只读视图 → `RouteDecision` 或无目的地 | 不写目录/账本，不打开网络，不执行 KV 迁移 |
| M5 | 复用宿主接入/发送/响应流；发送前 reserve，输出生命周期事件 | 选点不算发送；客户端断开不算后端结束；不得按 5xx 盲目重发 |
| M7 | 固定版本能力/实例身份、事件解码/恢复和健康来源 | 不吞版本不符，不逐请求同步设备，不凭 URL 相同认定实例没变 |
| M6 | 统一脚本、合同/故障/基准、制品与证据 | fixture 成功不等于真实 Router/NPU 成功 |

代码端口见 [contracts.py](../../src/prefix_routing_mod/contracts.py)；详细语义见 [合同](../contracts.md)。它是标准库语义参考，不是生产架构强制 Python，也不要求逐请求对象序列化或额外网络跳数。

## 三个工作包，可以怎样并行

| 包 | 职责和预期代码范围 | 现在可独立开始 | 必须等待的部分 / 退出条件 |
|---|---|---|---|
| A：后端与缓存可信性 | M7/M2：能力检查、事件规范化、恢复/失效状态机，候选索引 adapter | 核对固定协议；补正常/缺口/超窗/新旧代次 fixture；定义可恢复范围；规划 G2 压力用例 | 生产索引绑定等宿主准入；G2 完整通过才能宣称精确恢复。不得另造生产索引 |
| B：请求与执行链 | M1/M4/M5：模板/token 接口、基础策略接缝、生命周期桥 | M1 合同、精度降级、纯函数策略测试；审计宿主选择/发送/SSE/取消/重试接缝 | 生产 M5 与优化入口等底座决定；通过真实慢客户端、断开、发送前后故障及流式测试 |
| C：账本与集成交付 | M3/M6 + MOD 规范、CI、联调 | 用版本化用例校核幂等、重试、保留未知、代次隔离；合同/制品测试；资源预算设计 | 生产账本语言绑定等宿主决定；MOD 启停、两副本、容量评测分别验收，不能只跑单元测试 |

上述是任务包而非指定人员。每包自己写测试，另一个成员交叉审查；C 不是全队唯一测试负责人。共享契约文件由集成负责人维护，修改通过 ADR/版本升级，不能三人各改一套字段。禁止多人操作远端同一 checkout；独立分支/工作区，集成提交统一同步测试服务器。

现阶段可并行的是合同、独立语义与故障测试；**生产 M2/M5 的代码位置、宿主扩展 ABI 及发布二进制不能说已经确定**。先完成 R1 再将这些任务分配成大量实现工作，避免各人围绕不同假设开发。

## 合并与实现准入

- 契约变更、模拟用例和文档同一 PR，CPU 3.11/3.12 + Linux aarch64、loopback mock、sdist/wheel/干净安装；新增类型导入不得加载引擎或连接网络。
- 自检记录输入/输出、并发竞争、重复/冲突事件、旧代次、未知与陈旧观测、上限行为。草稿 PR 待其他成员审查，不自动合并。
- 生产实现另外补：有界队列/索引/账本留存、配置发布与排空线性化、异常 worker 对账、可靠本地生命周期投递、关闭顺序和目标负载开销。测试 oracle 故意达到容量就拒绝，不充当具备 GC/持久化的生产账本。
- Router 进程重启后丢失未决账本，不能直接推断后端空闲；恢复/保守排空未建立前该场景不通过。真实取消证据缺失时保留 unknown，并限制新增流量与禁用自动重试。
