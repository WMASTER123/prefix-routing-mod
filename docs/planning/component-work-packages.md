更新：2026-10-22。完成情况以 [progress](../progress.md) 为准，旧讨论保存在 [历史记录](component-work-packages-history.md)。本页给出职责和准入条件，尚未指定人员；实际端口、线程/错误边界及文件协调规则见[接手指南](../项目接手指南_2026-10-17.md)。当前具体交付/目录迁移与开销任务见[生产工作包](production-runtime-and-overhead.md)。

## 已确定的实现形态

一个 Rust Router 进程承载原 HTTP/SSE、M1 特征、M2 原索引、M3 状态与准入、M4 选点。固定宿主为 `vllm-project/router@91b65ee`；推理后端为 HUST Core `ced6857` / Ascend `b47795c`。它们是分别验证的仓库，不根据上游版本号互相推断兼容性。

Python 包负责 MOD 描述、doctor、版本映射和可选后端适配。M6 评测在请求链外；M8 在基础开销与收益明确后再考虑。MOD 当前保持 `import_only`。

```text
HTTP → M1 → M4 → M3 reserve → M5 原宿主发送/SSE
            ↑       ↑                   ↓
         M2 目录   M3 状态 ← 可靠后端终态
            ↑
       M7 事件/实例身份/控制租约
```

原索引、Directory/Pool 与本地适配只保留一个 owner。请求派发不能产生 KV 驻留事实；HTTP 结束不能直接释放已发送负债。

## 现在分工，生产接口另设冻结门槛

可以现在指定 A/B/C 人员并提交小范围实现 PR，不再把完整恢复、性能验收作为所有人开工的前提。当前按接手指南的候选端口协作；共享类型、存储合同、宿主接缝和配置由一名集成负责人协调。下面是生产冻结门槛，不是人员分工门槛。

首轮任务建议（2026-10-22 收敛）：A 保留已通过的控制门资格，补来源 fixture、升级反例与目录大工作集回归；B 完成输入边界、一次分词/代理成本和慢客户端回归；C 在已有持续驱动及 HTTP 运输 CPU 联调上完成新路径 NPU 资格、常驻排空与生产交付，并准备同底座开销对照。控制门准入/发送、回复丢失、520 family/1040 child 和限定崩溃恢复已通过，作为保留回归，不再重复列为待实现。A 联审来源语义、B 联审入口与取消语义。每组负责本组测试，C 协调 M6；任务卡列代码范围、端口、验收命令和不改动项，接口变更统一评审。

- 固定宿主真实公开入口同时使用 Qwen M1、M7→M2、M3 准入、M4 基础选点、M5 转发与真实终态；有干净环境启动命令和两个 TP1 配置。
- 记录每个端口的实际位置、调用线程、时钟、错误/超时、降级、配置发布和启停所有权；替身与正反例可独立运行。
- 真实请求链覆盖正常、重复、取消、断连、目录缺口、配置竞争与 Router 重启；未决负债保留，旧实例不能影响新实例。
- M3 持久介质和提交边界明确；终态 ACK/回收不能早于持久提交。超过早期 64 family/256 child 的持续运行有证据，资源满额行为明确。
- 基础开销检查排除重复分词、逐请求跨进程目录查询及明显锁/持久化瓶颈。正式容量和高级算法可以在分工后继续完成。
- 交叉审查通过后，记录接口版本、生产目录和交付方式，再允许基于冻结接口自由扩展；人员可提前确定并开展上述工作，但不能把候选类型当冻结 ABI。
