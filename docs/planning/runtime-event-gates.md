## G2 必须验什么

| 项目 | 通过条件；不能接受的替代 |
|---|---|
| 连接 | 首先同机 IPC 发布端 bind、订阅端 connect，独立私有 socket 路径；传输可用后再决定跨节点 TCP 方案，不绑定公共 wildcard 绕过问题 |
| 存储 | 真实请求生成 BlockStored；检查 framing、序号、block/group、parent、token/hash 语义及来源，不用合成事件冒充 |
| 淘汰 | 受控工作集超过实际可用 KV 容量，观察真实 BlockRemoved；清空缓存不能替代自然淘汰 |
| 清空 | 后端 reset 后目录相应失效；检查空闲时是否延迟到下一次调度才发布，不把 HTTP reset 返回当事件到达 |
| 重放 | 丢掉已知区间，验证 replay 起始序号、结束帧、去重、连续覆盖和上限；短窗口无法补齐必须保持 unknown |
| 断连 | 订阅断开立即失去目录可信资格；先恢复连续性再开放精确命中，不能以 HTTP 健康正常代替事件健康 |
| 重启 | 同地址启动新 epoch；旧目录/迟到旧事件不得进入新代次；序号归零本身不是完整身份认证 |
| 恢复 | 必须有已知起点和完整覆盖。普通 BlockStored 或再次连上 socket 不能让旧目录变为可信；无法恢复则明确降级 |

这些是测试合同，不是在本轮重写生产索引。先核对原生 replay/epoch 能力和成熟 Router 的恢复语义；不足再决定最小适配。原生事件不自带充分代次信息时，代次来源、接管启动前缓存的方式必须先形成 ADR。

## G3 和后续

- 固定一种目标图配置，记录实际生效值；eager 作为诊断对照。图预热和 KV 预热分开，配置不支持时明确失败。
- 并发覆盖短/长混合和容量边界，记录请求完成、错误、显存/Host 上限；不能只确认进程存活。
- 客户端中断后核验后端取消或明确未知状态、资源回收和后续请求可用，不把客户端关闭连接当完成取消。
- 重复启动/排空/关闭，覆盖异常退出和复原；仅清理自己创建的资源。
- 持续运行先约定时长、请求量、错误率、资源漂移与允许告警，再运行；未跑满不得宣告通过。
- 每个工作包带 CPU/mock、真机报告、自检和人工 PR 审查。NPU CI 暂不自动部署；无证据不更改能力矩阵或 MOD import_only。
