## 证据与必要性

固定 HUST `13f11da44455d2f85f00f810a04e1bd2eaf30ba6` 的四个文件先核验完整 SHA256，再抽取完整方法体执行。替身明确替代设备、分词器、队列、资源管理器；不导入引擎。见 `tools/audit_backend_terminal.py` 和[审计记录](backend-terminal-evidence.md)。

- `AsyncMPClient.abort_requests_async` 只发送 ABORT；`EngineCore.abort_requests` 调用清理但丢弃返回的请求列表。
- 管理性批量暂停/终止有单独 `_send_abort_outputs`，不能把它当作普通每请求取消的现成确认。不能为获得确认逐请求暂停整个服务。
- 前端 stop string 会先结束前端请求并删除外部/内部 ID 映射，然后要求核心取消。接收晚到终态时再读取该映射已经太晚。
- 核心 `_free_request` 之后可能还有 deferred block frees。因此逻辑请求结束不等于物理 KV 释放，更不等于设备全部空闲。不能靠逻辑结束增加可用 KV 计数。

## PR #13 初版原型（保留历史范围）

`tools/terminal_observer_prototype.py` 是单 owner、有限预算、进程内实验，不属于生产包。复用现有参考账本，不实现第二套代理或缓存索引。

1. 模拟发送前显式注册完整 attempt→child 集合，拒绝重复 ID、无界输入和超预算。真实父子 ID 的获取/封口尚未实现，禁止按字符串后缀猜测。
2. 在抽取源码构造的独立对象上，原始 `_free_request` 成功返回之后才调用 observer。原函数失败不发布成功终态；不替换原分配/清理逻辑。
3. 只有所有已登记子请求逻辑结束，才生成一个有限终态记录。记录不含 prompts、tokens 或逐 token 事件，也不判断用户请求成功/取消的原因。
4. 消费者在运行中调用既有账本，而不是等实验结束再重放。重复确认幂等；全部应用成功才 ACK；丢失 ACK、断连与序号缺口要求恢复。
5. 共同边界快照只提供明确 ended 的正证据；缺项不表示未接受。observer/instance 代次不符拒绝恢复，不能清掉旧账本。
6. 事件窗口满时已知故障使观测退出可用状态，返回失败但不向模拟调度器抛出。新登记拒绝；不以丢最旧记录制造成功。原型未知 child 也退出可用状态，生产前需要隔离非本 Router 管理的流量。

固定源码方法→journal→在线回调已接通；journal→现有账本以合成取消场景联调。**两者尚未合并为原生 Router—真实 HUST 的跨进程在线链路**。`OnlineConsumer` 是实验接口，不是生产 RPC/ABI。

## 生产候选接入面与成本

| 接入面 | 候选最小范围 | 尚须证明/否决线 |
|---|---|---|
| 请求关联 | 请求提交前取得真实外部/内部 ID 和完整 family；终态处理前保留关联 | n>1、多 prompt、chat、重试不可只猜一个 ID；若需重写请求入口，先重新讨论 |
| 核心终态 | 原始核心清理成功后的只读观测 | 不改 scheduler 决策、不接管 allocator/eviction、不插入设备同步；大范围继承/fork 则停止 |
| 控制侧投递 | 有界 journal、序号、ACK/快照与代次 | 不能在引擎热路径等待远程 ACK；跨线程/进程、鉴权与线长上限未实现 |
| Router 收敛 | 同一生命周期所有者将后端证据送入 M3 | 不允许 M5 与 observer 各自分配同一尝试的 lifecycle sequence；逻辑结束不能伪造请求成功 |
| 长期运行 | 活跃关联+有限终态留存；可靠去重与 GC/恢复规则 | 当前保留 tombstones 到预算满后拒绝，**不可作为可持续生产实现** |
| 关闭/失效 | 无安装即原生行为；生产默认关闭与固定源码守卫 | 关闭不能把未结清负债置零；现有 CPU 工具守卫不等于插件安装/卸载已验证 |

每个子请求至多一次有效结束更新、每个 family 一条终态记录；登记和快照成本随 family/留存规模增长。没有逐 token RPC，也不把 observer 的 Python 实验实现冻结为生产热路径。需测 NPU Host 竞争、流式尾延迟和协议恢复，不把 CPU 方法耗时当请求延迟。

## 下一步与退出条件

- 第 1 步：真实 ID 获取/完整封口、正常/stop string/取消结果语义和可逆安装点确认；当前只证明方法接缝可行。`BackendConfirmation.ENDED` 的候选含义是“不再调度该逻辑请求”，不能充当 NPU idle/HBM free 信号；生产合同冻结前需确认。通用 ended 不应直接映射为 COMPLETED。
- 第 2 步：原生 M5 唯一序号所有者、发送前确认、终态 inbox、重复/断连恢复，以及 Router 整进程重启后的账本恢复。当前测试只重建 consumer 且保留账本，**不是持久化恢复**。observer 丢失历史则隔离受影响派发并保留负债，不自行启新代次当恢复成功。
- 第 3 步：M7→M2 wire/新鲜度及全池预算不变；尚未开始新的真实 KV 接线，不受本原型的 pass 自动放行。
- 上述关键接缝通过再冻结首版目录和生产接口；不再添加算法/M8。当前 CPU 足够；真实后端确认和图模式需要时通知 1 张 NPU，双副本再用 2 张。

CPU 检查不涵盖真实自然结束、真实 detokenizer、IPC 丢包、kill -9、完整 shutdown loop、异步 NPU fence 或长期吞吐。自审与测试通过也不能替代另一成员独立审查。
