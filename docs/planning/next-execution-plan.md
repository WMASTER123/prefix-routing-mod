## 3. W2：真实 KV 事件回归（G2，下一主要开发工作）

当前进展：[生命周期子集](../../evidence/g2-native-events-subset-2026-10-11.md)、[恢复故障子集](../../evidence/g2-recovery-regression-2026-10-11.md)及[身份/publisher 子集](../../evidence/g2-identity-publisher-2026-10-11.md)已有实证。纯文本身份已对齐；用户批准的可选 hook 通过串行已热冷接入、超窗 token 快照、快照加增量、清空和同地址重启，默认仍关闭。下一工作为压力/自然淘汰下的身份和快照重验、恢复竞态、队列/元数据/RSS 与开销测量；通过后再进入 G3。完整 G2 尚未通过，不能用拒绝快照替代成功恢复，也不能将原生与实验协议的成绩混记。

交付是有限范围的协议测试接收器、CPU 故障用例及真实 NPU 回归报告，不是提前自研生产索引。

先针对固定 HUST 源码写清 framing/tagged map、hash/token/block/group、parent 链、epoch、序号、重放和快照语义，再以真实流量验证。Host 发出事件不自动代表 NPU 计算完成；可复用语义按引擎实际生命周期判定。

| 用例 | 实施与验收 |
|---|---|
| 真实存储与身份 | 同机私有 IPC，关联请求与事件；验证完整块、group/parent/hash、重复事件处理，不记录原始用户 prompt |
| 自然淘汰 | 按实际 KV 可用块数构造超容量工作集；必须看到真实移除，不能用 reset 替代。必要时使用单独标明的小容量测试配置，不混入性能基线 |
| 清空 | 验证 reset 与清空事件的实际关系，包括空闲后延迟发布；HTTP 返回成功不是目录已清空的证据 |
| 重放 | 注入已知缺口，核验范围、去重和完整性。legacy 结束帧与 HUST 结构化响应按各自协议判断，不强套同一解析器 |
| 窗口溢出与快照 | 缺口超过可重放范围时保持 unknown；验证快照覆盖范围及快照与增量的接续边界，接口存在不等于原子一致 |
| 断连与静默 | 显式断连或检测到连续性丢失即撤销可信资格；设定可测的失联检测/陈旧时限。连接未报错不代表仍收到所有事件 |
| 进程重启 | 同地址新进程不继承旧目录；验证 epoch 或外部生命周期身份、迟到旧事件拒收，不能只依赖序号归零 |
| 冷接入与恢复 | 中途接入已热服务也须建立已知起点、范围及完整覆盖。重连或单条 BlockStored 不能恢复整个目录的可信性 |

通过条件：正向和故障用例可重复运行，每项有明确 pass/fail/not-run；测试接收器的可信状态转换与协议合同一致，恢复缺口不会伪装成命中。限制、未支持传输和最小可恢复条件写入能力矩阵。

原生接口缺口已复现并形成 [ADR](../decisions/2026-10-11-optional-hust-publisher.md)，用户选择窄幅可选 hook 实验。正式交付尚待开销、维护边界与目标配置审查；精确模式达不到时保留未完成状态，不得为了通过验收把精确模式悄悄改成请求历史估计。跨节点 TCP 后续独立验证，同机 IPC 通过不能替代。

## 4. W3：单后端可用性与性能配置（G3）

G2 完成后，固定一套真正用于后续比较的 Ascend 执行配置。已有 eager + COMPILE_CUSTOM_KERNELS=0 是可行性对照，不直接当作高性能最终基线。

- 按固定 HUST/Ascend 源码核验目标图模式和自定义 kernel 的构建要求；选择有依据的主配置、重新记录有效 KV 容量和执行指纹。必要构建仅在项目隔离目录内，不改全局工具链。
- 分开验证图预热与 KV 预热，分别记录冷启动、稳态和重复前缀；不能把二者的耗时变化都归为缓存收益。
- 验证 Completions 和 Chat Completions 的声明范围、流式/非流式、模板/tokenizer 一致性。现有普通生成成功不代表聊天接口或精确 token 身份通过。
- 覆盖并发、长短混合、客户端取消、超时、排空、重复启停和异常退出；取消须检查后端状态/资源回收，不能只看客户端断开。
- 先做有界并发校准，再在运行前固定持续测试的时长、请求量、错误门槛和内存/队列漂移标准；不得完成后倒推合格线。资源采集使用低频或现成指标，不在逐请求路径调用 npu-smi、profiler 或设备同步。
- 如果图/构建变化影响事件生产路径或身份，同步重跑受影响 G2 用例，不继承旧配置成绩。

退出条件：主配置及支持范围明确，兼容/稳定性报告通过；未跑图、取消或持续运行的项目不能以 eager smoke 代替。性能测试独占时段仍须确认。

## 5. W4：成熟 Router 准入和两副本闭环（G4）

真实接线在前面通过后进入此包；其中源码审计和 CPU 构建准入 R1 可以先做。vLLM Router 是首个候选，不是已冻结底座；不同时引入 Dynamo、llm-d 和多套代理。

1. 固定候选提交，审计 Linux aarch64/无 CUDA 最小依赖、许可证、公开扩展接口和 Manager 外部 Router 契约。
2. 对照已验证的 HUST 事件合同检查现有索引是否真正兼容，包括 token/hash/group/epoch、快照和失效语义；普通 HTTP 可通不代表精确缓存匹配正确。
   同一固定 Router 91b65ee 的进一步审查已确认索引尚未在在线策略中接线，且 native legacy replay framing 不兼容；应把 M2→M4 接线、原子快照安装与 bounded anchor GC 纳入准入改动范围，再评估维护成本，不据库导出就冻结底座。
3. 若能通过小适配接入，复用代理、索引和生命周期；若需要大面积 fork，记录不通过原因并通过 ADR 决定替代，不先另写一套代理/索引。
4. 接两个 TP=1 Qwen14B 副本，先验证正确转发、流式、取消、故障退化与恢复，再建立直连、仅代理、负载基础策略、缓存感知强基线。
5. 将状态接收、索引和策略开销分开测量，连同分词、压测器和引擎的 Host 争用计入预算。

退出条件：两副本可用闭环和可复现基础报告；能解释额外开销与退化。实际启停、回退及目标 Manager 合同未完成前，MOD 继续 import_only，不能为展示而放开 enable。

## 6. 之后才选择优化方法

用强基线找实际损失：稳定共享、低复用、热点变化、长短混合及超容量工作集。优先改影响最大的瓶颈；后台亲和、预测或干扰保护逐项消融，未证明净收益的不默认开启。G1–G3 使用可控合成请求即可，不需要先下载大数据集；G4 后再选公开负载并记录来源、许可和变换。

性能主指标仍是相同 NPU/Host 预算下，满足 TTFT、客户端可见输出停顿和完成率约束的可持续容量；同时报告尾延迟、错误/拒绝、队列增长及控制成本。没有业务 SLO 时先校准并固定多档阈值，不能只展示命中率或挑选有利场景。
