# 架构基线

## 要解决的问题和评价边界

现有多副本服务中，前缀复用带来的计算节省可能被排队、拥塞、重复建立缓存和状态失真抵消。本项目优化同构池的请求分配，使缓存收益实际转化为达标容量；不预设成熟系统已经失败，必须先测强基线及本环境瓶颈。

主要指标是在固定 NPU / CPU / 内存资源下，同时满足 TTFT、输出停顿和完成率要求的可持续容量。不得只报命中率或平均吞吐。低复用、热点变化和混合长度负载必须纳入负对照。

华为 Ascend 是主要目标，不只是兼容附件。缓存命中节约的实际工作、ACL Graph/批量形状、有效 KV blocks 和 aarch64 Host 开销需要目标配置校准；不照搬 GPU 成本系数。机制、证据和能力缺失行为见 [Ascend 设计约束](ascend-design.md)。

## 一条在线链路，而不是八个服务

```text
客户端 -> M5 接入/生命周期 -> M1 特征 -> M4 选点 -> M5 执行 -> 已有模型副本
                                            ^
                                      M2 缓存状态 / M3 工作量
                                            ^
                                      M8 可关闭的软亲和计划
已有副本 -> M7 原生接口适配 -> M2 / M3
M5 结果 -> M3 对账、M8 有界历史、观测
M6 测试/校准/评测在请求路径之外运行
```

首版一个外部 Router 进程；现有推理副本独立运行。即时状态更新不属于“慢路径”；M8 只是异步计算未来软偏好，失败或过期不能阻塞当前请求。快慢分离是控制结构，不是已证实的性能创新。

| 职责 | 输入/输出与所有权 | 复用和自研边界 | 首次验收 |
|---|---|---|---|
| M1 请求特征 | 真实模型身份、模板与 token/block 特征；不维护副本缓存树 | 复用 tokenizer/模板，补兼容域与精度契约 | P1/P3 |
| M2 缓存目录 | 事件到驻留记录、连续匹配、置信与代次 | 优先宿主索引；仅确有缺口再比较 Dynamo/llm-d 方案，不并行部署多套 | P3 |
| M3 状态与账本 | 健康、代次、在途工作和终态对账的唯一所有者 | 复用健康基础设施，自研必要的对账/覆盖语义 | P2/P3 |
| M4 即时选点 | 读取状态与软计划，输出可解释决定 | 复用基础策略和策略入口，候选优化后选 | P4 |
| M5 转发与生命周期 | 请求、连接、实际发送、终态事件唯一来源 | 首先验证 vLLM Router；不从零重写网关 | P1/P2 |
| M6 校准评测 | 负载、故障与指标到可复现证据 | 复用成熟压测工具，补 SLO 口径、统一入口与消融 | 全程 |
| M7 宿主/MOD 适配 | 版本、原生事件/指标、能力预检与交付 | 复用组内模板/Manager；observer 仅缺观测时引入 | P0/P1/P7 |
| M8 后台亲和 | 有界历史到版本化软计划 | 自研控制契约，借鉴方法，净收益通过才默认开启 | P5 |

配置原子切换、日志与指标基数上限、请求大小/队列/索引上限、鉴权与身份隔离、排空、故障恢复贯穿各模块，不能遗漏，也不能为了目录整齐变成多次网络调用。

## Ascend 能力与执行档案（规划）

M7 产生 BackendCapability，M6 产生 ExecutionProfile；经 M7 校验后由 M3 持有引用，M4/M8 读取本地不可变版本。这是现有职责间的数据合同，不增加两个在线服务。能力报告涵盖整栈、模型/布局/设备映射和观测来源；校准档案包含执行指纹、适用范围、冷暖条件、误差与证据，不是单个 tokens/s 常量。

语义兼容域、缓存布局/事件协议和执行性能指纹分别管理。过期/未知档案不能用于宣称准确成本；CPU/图配置变化按影响失效档案，缓存身份变化失效相应目录，重启由 epoch 处理。见 [契约](contracts.md)。

阶段信息可选且有成本上限；Router 不拥有引擎实际 batch、图桶或 KV 淘汰权。精确事件不足时退出精确模式；性能档案不足时回退基础策略。原生观测先验收，小型 hook 不能破坏异步/图执行，也不能因“指标准确”在热路径同步设备。

## 当前代码和最终运行时的关系

现在的 Python 包仅承载配置预检、静态 MOD 描述和测试工具。未固定生产 Router 的语言/二进制布局，没有把 Python 脚手架当成既定性能方案。P1a 必须验证公开策略/生命周期/索引接入点、aarch64 构建及必要修改范围，再冻结宿主选择。

未来新增策略必须在同底座基础策略上增量比较；协议转发、取消、健康等优先复用。跨底座整体比较和同底座策略消融分别报告。

## 暂不纳入

不做 P/D、分层缓存、跨副本 KV 搬运、异构调度、引擎淘汰替换、模型部署平台、多 Router 高可用。组件接口为扩展留空间，不以预留接口宣称已支持。
